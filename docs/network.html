Chapter 03

A network that knows nothing

One number in, one number out, 2,209 weights between them, and no idea what a spring is.

The model is a multilayer perceptron: time goes in, position comes out, and between them are three hidden layers of 32 neurons. Each layer multiplies by a matrix, adds a bias and applies tanh. That gives 64 + 1,056 + 1,056 + 33 = 2,209 trainable numbers. the class

The useful way to think of it here is as a function: a smooth curve with 2,209 knobs, defined at every real t, including times where there is no data.

Three choices in the code

Time is rescaled to [−1, 1]. tanh is most curved near zero. Feeding in raw seconds from 0 to 1 would put every input on one side. The rescaling happens inside forward, so autograd sees it, the chain rule includes the factor of 2, and derivatives come out per second.

Everything is float64. Second derivatives magnify rounding error, and the optimiser used later compares losses that differ only in the seventh digit, which is where float32 runs out.

The seed is private. Each network draws its weights from its own generator, so the plain net and the PINN with the same seed start out identical. The first version failed its test: nn.Linear draws default weights from the global generator before they are overwritten. skip_init prevents that.

The plain net

The baseline is trained on one thing, the mean squared distance to the ten dots. Adam runs for 3,000 steps. The data loss ends near 3.3 × 10−5, below the noise variance of 10−4, so as a fit to the dots it is excellent.

Over ten seeds the error after the dots ranges from 0.1 to 3.4, with a median of 1.6. Always answering zero scores 0.078. All ten plain nets are worse than a constant.

Training harder makes it worse. With L-BFGS switched on, the median rises to 4.9, because the extra effort goes into bending the curve through the noise. A small wiggle inside the window becomes a large one outside it.

IN:Isn't this just overfitting? Would more regularisation fix it?
OUT:

Overfitting the noise is part of it, and weight decay or early stopping could reduce that part. But even a perfect fit inside the window says nothing about the outside. Regularisation pulls the continuation towards something smooth and small, perhaps towards zero, and zero is still wrong. The missing ingredient is information about how the system moves, and regularisation doesn't contain any.
